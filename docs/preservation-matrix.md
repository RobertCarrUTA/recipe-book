## Explicit scope distinctions

The old app has one fixed dark theme, one grocery list, a weekly template (no dated calendar or meal slots), no recipe editing, no interactive user ratings, no cooking timers, no persisted cooking progress and no print control/print stylesheet. Do not claim these as old features. Light/Dark/System is a new required capability. Standard browser printing must remain usable. Grocery scaling must not invent scaled recipe prose or nutritional values.

## Baseline material findings

Independent in-memory reproductions found legacy multipliers deleted during migration, a malformed schema-v1 backup normalized to empty state, and mixed durable state after a failed multi-key save. Existing targeted tests passed and therefore did not protect these cases. #172/#141 must add failing characterization before fixes. #140 already describes stale/mixed shell versions; real browser upgrade verification remains required.

Completion requires replacing every pending location with the implemented boundary, linking protecting tests and reviewed visual evidence, and accounting for any intentional behavior change. Passing the legacy suite alone does not establish redesign parity.
